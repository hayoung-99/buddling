# tap-tap

바탕화면 위에 3D 동물 친구를 띄워두고, **내 캐릭터를 클릭하면 팀원들의 화면에서 캐릭터가 춤을 춥니다.**

말을 걸지 않고도 "나 여기 있어"를 전할 수 있는 가벼운 인터랙션이에요.

| | |
|---|---|
| 캐릭터 | 해피 캣 · 터비 독 · 퍼지 판다 · 덤 덕 · 홉 버니 (5종) |
| 플랫폼 | macOS · Windows · Linux (Electron) |
| 참여 방식 | 계정 없이 닉네임 + 6자리 초대코드 |
| 언어 | 한국어 · English · 日本語 · 中文 (기본은 시스템 설정을 따름) |
| 팀 | 한 사람이 최대 **3개** 팀까지, 팀 하나에 최대 **5명**. 팀마다 캐릭터가 한 마리씩 뜹니다 |
| 초대코드 | 발급 후 **24시간** 뒤 만료. 언제든 새 코드로 갈아끼울 수 있습니다 |
| 절전 | 부드럽게 · 균형(기본) · 절약 3단계. 컴퓨터를 켜둔 내내 떠 있는 앱이라 고를 수 있게 했습니다 |

---

## 시작하기

Node 는 `.nvmrc` 에 적힌 버전을 씁니다 (nvm·fnm 이 이 파일을 읽습니다).

```bash
nvm use
npm install
```

### 1. Supabase 준비 (약 5분, 한 번만)

팀 정보 저장과 실시간 전달에 Supabase 무료 플랜을 씁니다.
[docs/SUPABASE_SETUP.md](docs/SUPABASE_SETUP.md) 를 따라 프로젝트를 만들고 키를 넣어 주세요.

```bash
cp env.sample .env   # 그리고 SUPABASE_URL / SUPABASE_ANON_KEY 를 채웁니다
```

키가 없어도 앱은 실행됩니다. 팀 창이 무엇을 해야 하는지 안내해 줘요.

### 2. 실행

```bash
npm start
```

캐릭터가 화면 오른쪽 아래에 나타나고, 팀 창이 함께 열립니다.
이름을 정하고 팀을 만들면 6자리 초대코드가 나옵니다. 팀원에게 그 코드를 알려주세요.

팀은 **최대 3개**까지 만들거나 참여할 수 있고, **팀 하나당 캐릭터 한 마리**가
화면에 뜹니다. 팀마다 다른 캐릭터를 골라 두면 어느 팀에서 온 신호인지 한눈에 보여요.

## 이렇게 씁니다

- **캐릭터 클릭** → 그 캐릭터가 움찔하며 말풍선을 띄우고, **그 팀** 팀원들의 캐릭터가 춤을 춥니다
- **캐릭터 끌기** → 원하는 자리로 옮깁니다 (다음 실행에도 그 자리에 있어요)
- **캐릭터 우클릭 → 크기 조절** → 슬라이더로 25%~200% 사이에서 크기를 정합니다
- **캐릭터 우클릭** → 이 팀 자세히 보기 / 팀 목록 열기 / 크기 조절 / 캐릭터 모두 숨기기 / 종료
- **메뉴바 아이콘** → 팀 상태 확인, 캐릭터 보이기·숨기기
- **팀 창의 `콕!` 버튼** → 특정 한 사람만 콕 찌릅니다

**보이는 모습으로 무슨 일인지 구분됩니다.**

| 보이는 것 | 뜻 |
|---|---|
| 좌우로 흔들며 춤추고 음표가 떠오른다 | 그 팀 누군가 나를 콕 찔렀다 (발밑 이름표에 누구인지) |
| 움찔하며 `TAP TAP!` 말풍선이 뜬다 | 내가 내 캐릭터를 눌렀다 |
| 둘이 한꺼번에 | 같은 순간에 일어났다 |

여러 명이 동시에 찔러도 **춤은 한 번**입니다. 대신 **이름표는 찌른 사람마다** 하나씩
발밑에 나란히 붙습니다.

화면의 자리를 셋으로 나눠 서로 겹치지 않게 했습니다 — **머리 위**는 내가 눌렀을 때의
말풍선, **좌우**는 춤출 때 떠오르는 음표, **발밑**은 누가 찔렀는지.

캐릭터 옆 빈 공간은 클릭이 그대로 바탕화면으로 통과하므로, 아이콘을 가리지 않습니다.

캐릭터·크기·위치는 **팀마다 따로 저장되고 내 화면에만 적용되는 개인 설정**입니다.
크기를 바꿔도 발밑이 붙박여 있어 캐릭터가 제자리에서 커지고 작아집니다.

### 배터리를 아끼는 법

컴퓨터를 켠 순간부터 끌 때까지 떠 있는 앱이라, **아무 일도 없을 때 얼마나 게으르게
구는가**가 곧 배터리와 팬 소리를 정합니다. 트레이 ▸ 설정에서 세 단계 중 고릅니다.

| 단계 | 가만히 있을 때 | 찔렸을 때 | 캐릭터 3마리 기준 |
|---|---|---|---|
| 부드럽게 | 화면 주사율 그대로 | 그대로 | 약 9% |
| **균형** (기본) | 초당 30프레임 · 그림자 고정 | 초당 60프레임 | 약 5% |
| 절약 | 초당 10프레임 · 해상도 절반 | 초당 60프레임 | 약 3% |

어느 단계에서든 호흡·눈깜빡임·귀 쫑긋·꼬리는 그대로 살아 있고, 누가 찌르면 곧바로
넉넉한 프레임으로 올라갑니다. 그리고 단계와 무관하게 **캐릭터를 숨기거나 컴퓨터가
잠들면 아예 그리지 않습니다** (0%).

CPU 수치는 M 시리즈 맥에서 `TAPTAP_METRICS=5 npm start` 로 잰 값입니다.

## 개발

```bash
npm run build         # 화면(React·TS)과 preload 를 빌드한다 — 실행 전에 한 번은 필요하다
npm run dev           # 화면을 고칠 때마다 다시 빌드한다 (창은 새로고침)
npm test              # 단위 테스트 (vitest) — Supabase 없이 돈다
npm run typecheck     # 타입 검사
npm run lint          # 린트 (oxlint)
npm run check         # 실제 Supabase 연결 점검 (.env 필요)
npm run preview       # 캐릭터 5종을 나란히 놓고 비율·애니메이션 확인
npm run tray-icon     # 메뉴바 아이콘 PNG 다시 생성
npm run app-icon      # 앱 아이콘(icns·ico·파비콘) 다시 생성
npm run site-images   # 랜딩페이지에 쓰는 그림 다시 생성
npm run site          # 랜딩페이지를 Vercel 과 같은 규칙으로 로컬에서 띄운다
npm run site:open     # 띄우고 브라우저까지 연다
npm run check:site    # 랜딩페이지가 스스로 어긋나지 않았는지 (CI 도 이걸 돌린다)
npm run dist          # 설치 파일 만들기 (접속 정보를 앱에 구워 넣습니다)
```

`npm run check` 는 기기 두 대인 척하며 팀 만들기 → 초대코드 참여 → 콕 찌르기 →
접속 상태 → 팀 나가기까지 진짜 RPC·Realtime 을 거쳐 확인하고, 만든 데이터는 지웁니다.
Supabase 설정을 바꿨거나 스키마를 다시 실행한 뒤에 돌려보면 좋습니다.

### 혼자서 두 명인 척 테스트하기

한 대의 컴퓨터에서 A·B 두 명을 동시에 띄울 수 있습니다.

```bash
npm run start:both
```

터미널을 두 개 쓰고 싶다면 따로 실행해도 됩니다.

```bash
npm start              # A
npm run start:second   # B
```

`TAPTAP_PROFILE` 로 userData 경로가 갈라지므로 **서로 다른 사람으로 취급**됩니다
(로그인 세션·팀 소속·캐릭터·창 위치가 각각 따로 저장됩니다).

두 번째 인스턴스의 캐릭터는 첫 번째 왼쪽에 떨어져 뜨고, 메뉴바 아이콘에 마우스를 올리면
`tap-tap (second)` 로 표시되어 구분됩니다.

**해볼 순서**

1. A의 팀 창에서 이름을 넣고 팀을 만듭니다 → 초대코드가 나옵니다
2. B의 팀 창에 그 코드를 넣고 참여합니다
3. **A의 캐릭터를 클릭** → A는 움찔하며 `TAP TAP!`, **B는 춤추며 발밑에 A의 이름**이 떠오릅니다
4. 서로 다른 캐릭터를 골라 보고, 우클릭 → 크기 조절도 각각 따로 적용되는지 봅니다
5. A에서 팀을 하나 더 만들어 보세요 — 캐릭터가 한 마리 더 뜨고, 그 캐릭터를 눌러도
   먼저 만든 팀에는 신호가 가지 않습니다

`npm run start:both` 은 터미널에서 `Ctrl+C` 한 번이면 둘 다 함께 종료됩니다.

> 두 인스턴스가 같은 Supabase 프로젝트를 보므로 `.env` 는 그대로 하나만 있으면 됩니다.

### Supabase 없이 화면만 둘러보기

```bash
TAPTAP_FAKE_NET=1 npm start
```

메모리 안의 가짜 서버를 씁니다. 팀 만들기·캐릭터 고르기 같은 화면을 전부 눌러볼 수 있지만,
같은 프로세스 안에서만 통하므로 인스턴스 사이 통신은 되지 않습니다.

## 구조

저장소는 **npm workspaces 모노레포**입니다. 명령은 루트에서 부르면 되고, 루트 명령이
알맞은 워크스페이스로 넘겨줍니다.

**소스가 아니라 빌드 산출물이 돕니다.** `npm start` 가 알아서 먼저 빌드하지만, 소스를
고친 뒤에는 `npm run build` (또는 `npm run dev`) 를 거쳐야 창에 반영됩니다.

```
apps/
└── desktop/           Electron 앱. 이 폴더가 통째로 하나의 앱이다
    ├── src/
    │   ├── main/          메인 프로세스 (타입스크립트 → CommonJS 로 빌드된다)
    │   │   ├── main.ts         진입점 · 팀 수에 맞춰 캐릭터 창을 만들고 지운다
    │   │   ├── windows.ts      투명 캐릭터 창 / 팀 창 / 크기 조절 패널
    │   │   ├── session.ts      저장소 · 네트워크 · 창을 잇는 상태 한 곳
    │   │   ├── store.ts        userData 안 JSON 한 개
    │   │   ├── ipc.ts          렌더러와의 유일한 통로
    │   │   ├── click-through.ts  캐릭터 위에서만 마우스를 받기, 끌어서 옮기기
    │   │   ├── pet-size.ts     창 크기 계산 (Electron 없이 테스트 가능)
    │   │   ├── tray.ts         메뉴바 아이콘
    │   │   ├── i18n.ts         지금 쓰는 언어 하나를 들고 있는 얇은 껍데기
    │   │   ├── updates.ts      새 버전을 어떻게 가져다줄지 플랫폼 보고 정한다
    │   │   ├── update-schedule.ts  언제 확인할지 (아침에 하루 한 번)
    │   │   ├── auto-update.ts  받아서 설치까지 (Windows)
    │   │   ├── update-check.ts 나왔다고 알리기만 (그 밖 · 내려받기 실패 시)
    │   │   └── config.ts       Supabase 접속 정보 (개발용 파일 / 빌드에 구운 값)
    │   ├── preload/       렌더러에 노출할 좁은 API (CommonJS 로 빌드된다)
    │   ├── renderer/      React + 타입스크립트 + Tailwind
    │   │   ├── theme.css       색·모서리 토큰과 Tailwind 바탕
    │   │   ├── ui.ts           여러 창이 되풀이해 쓰는 유틸리티 묶음
    │   │   ├── pet/            Three.js 캐릭터. 렌더 루프는 명령형이고 React 는 껍데기만
    │   │   ├── team/           팀 목록 창(TeamList) + 팀 상세 창(TeamDetail)
    │   │   ├── settings/       절전 강도·언어를 고르는 창
    │   │   ├── size/           캐릭터 크기 조절 패널
    │   │   ├── preview/        개발용 캐릭터 미리보기
    │   │   ├── icon/           앱 아이콘을 그리는 화면 (배포본에는 안 들어간다)
    │   │   └── site-assets/    랜딩페이지 그림을 그리는 화면 (배포본에는 안 들어간다)
    │   └── services/      net.ts 인터페이스 · supabase-net · 테스트용 fake-net
    ├── test/          단위 테스트 (Electron 없이 돈다)
    ├── scripts/       앱에 딸린 도구 (아이콘 · 접속 정보 굽기 · e2e 점검)
    ├── assets/        트레이 아이콘
    ├── build/         앱 아이콘 산출물 (icns · ico · png)
    └── dist-main/ · dist-renderer/ · dist-preload/   빌드 산출물. 실제로 도는 것은 이쪽이다

apps/
└── web/               랜딩페이지 (Next.js · Vercel 로 올라간다)
    ├── app/           (ko) 는 `/`, (en) 은 `/en` — 나라말마다 루트 레이아웃이 하나씩
    ├── components/    마크업 한 벌. 나라말은 밖에서 들어온다
    ├── lib/           문구(copy.*.tsx) · 주소(site.ts) · 구조화 데이터(jsonld.ts)
    ├── public/        그림 · robots.txt · llms.txt
    └── middleware.ts  요청마다 nonce 를 발급해 CSP 에 싣는다

packages/
└── shared/            앱·랜딩·어드민이 함께 보는 것
    └── src/           characters · power · i18n/ · state · ipc

scripts/            랜딩 점검 (빌드한 결과를 띄워서 본다)
supabase/           schema.sql — 테이블과 RPC
```

아이콘도 랜딩페이지 그림도 **앱과 같은 캐릭터 코드로 그립니다.** 캐릭터 스펙을
고치고 `npm run app-icon && npm run site-images` 를 돌리면 전부 따라옵니다.

### 여러 나라 말

문자열은 [`packages/shared/src/i18n/`](packages/shared/src/i18n/) 안에 언어별 JSON 한 벌씩 있습니다.
열쇠(key)는 네 언어가 똑같아야 하고, 하나라도 어긋나면 테스트가 잡아냅니다 —
빠진 열쇠·남는 열쇠·`{빈칸}` 불일치·빈 문장까지 검사합니다.

처음 실행하면 **운영체제 언어를 따라가고**, 설정 창에서 직접 고를 수도 있습니다.
바꾸면 트레이·우클릭 메뉴까지 함께 바뀝니다.

오류 메시지는 통신 계층에서 문장을 만들지 않고 `error.INVITE_EXPIRED` 같은
**열쇠만 넘깁니다.** 그 계층은 지금 어떤 말을 쓰는지 모르기 때문입니다.

### 캐릭터는 코드로 그립니다

모델 파일(.glb 등)이 하나도 없습니다. `createCritter(spec)` 이 구·캡슐·원뿔을 조합해
5종을 만들고, 색·비율·귀 모양·꼬리 모양은 [`packages/shared/src/characters.ts`](packages/shared/src/characters.ts)
한 곳에서 정합니다. 새 동물을 추가하려면 그 배열에 항목 하나를 더하면 됩니다.

### 동작은 여러 겹이 겹쳐서 만들어집니다

| 겹 | 언제 | 무엇이 움직이나 |
|---|---|---|
| idle | 항상 | 호흡 · 눈 깜빡임 · 꼬리 · 이따금 한쪽 귀 쫑긋 |
| dance | 팀원이 찔렀을 때 | 좌우 이동 · 몸통 기울임 · 팔 흔들기 · 발 번갈아 들기 (0.84초 × 2바퀴) |
| twitch | 내가 눌렀을 때 | 제자리에서 좌우로 떨림 (0.46초) |

서로 곱해지고 더해지기 때문에 **동시에 일어나도 서로를 지우지 않습니다.**

살아있어 보이게 만드는 장치:

- **squash & stretch** — 웅크렸다 늘어나고, 땅을 딛는 순간 찌부러집니다
- **지연** — 귀·꼬리·머리가 몸통보다 한 박자 늦게 따라옵니다 (스프링)
- **반대 방향** — 몸이 기울면 머리는 덜 기울어 중심을 잡습니다

이동 폭·높이는 전부 **캐릭터 키의 몇 배**로 정의해서, 종이 다르거나 크기를 조절해도
화면에서 같은 비율로 움직입니다. 타임라인은 순수 함수라 브라우저 없이 테스트합니다.

폴짝 뛰기(`hop`)는 지금 앱에서는 쓰지 않지만 `npm run preview` 의 `폴짝` 버튼으로
비교해 볼 수 있게 남겨 두었습니다.

## 배포하기

저장소를 만드는 것부터 랜딩페이지를 올리는 것까지 [docs/RELEASE.md](docs/RELEASE.md)
에 순서대로 있습니다. 키 관리, 받는 사람이 겪는 보안 경고 안내, 앞으로 코드 서명과
자동 업데이트를 붙일 때 짚을 곳까지 정리되어 있습니다.

```
main 에 머지 → 랜딩페이지는 바로 배포되고,
               앱은 "다음 릴리스" PR 이 쌓인다 → 그 PR 을 머지하면 릴리스
```

새 버전을 내는 데 필요한 것은 **PR 하나를 머지하는 일**뿐입니다. release-please 가
커밋 메시지의 `feat:` / `fix:` 를 읽어 버전을 정하고 변경 목록을 적어 둡니다.

핵심만 요약하면:

- **anon 키는 앱 안에 들어갑니다.** 저장소를 비공개로 해도 숨겨지지 않으니,
  키가 알려져도 안전한 구조(RLS + security definer 함수)에 기대야 합니다.
- 키는 커밋하지 말고 **GitHub Actions 시크릿**으로 넣으세요. 태그를 밀면
  `.github/workflows/release.yml` 이 빌드해 Releases 에 올립니다.
- **비공개 저장소의 릴리스 파일은 외부인이 받을 수 없습니다.**
- **코드 서명이 없어 처음 열 때 경고가 뜹니다.** 넘기는 방법을 랜딩페이지
  ([`site/`](site/))와 릴리스 노트에 함께 적어 두었습니다. 이 안내가 없으면
  대부분 여기서 포기합니다.
- **Windows 는 자동으로 업데이트됩니다.** 조용히 받아 두었다가 팀 창의 배너를
  누르면 적용되고, 안 눌러도 다음에 종료할 때 갈아끼워집니다. macOS 는 코드 서명이
  없으면 구조적으로 불가능해서 "새 버전이 나왔어요" 안내만 띄웁니다.

### 랜딩페이지

[`site/`](site/) 는 빌드 도구가 없는 HTML·CSS 한 벌입니다. 한국어와 영어 두 페이지가
있고, 받기 버튼은 열릴 때 GitHub 의 최신 릴리스를 읽어 파일 하나로 좁혀 줍니다.
자바스크립트가 꺼져 있어도 릴리스 목록 페이지로 갑니다.

```bash
cd site && npx vercel --prod
```

## 알아두면 좋은 점

- 로그인 화면이 없습니다. 대신 Supabase 익명 로그인으로 기기마다 계정을 하나 만들어 두고,
  서버는 클라이언트가 넘긴 값이 아니라 `auth.uid()` 로 누가 부르는지를 가립니다.
  테이블은 RLS로 잠겨 있고 모든 접근은 `security definer` 함수로만 이루어집니다.
- 실시간 채널은 private 채널입니다. `realtime.messages` 정책이 "그 팀 멤버인가"를 확인하므로
  팀 ID를 알아도 팀원이 아니면 붙을 수 없고, 팀을 나가면 그 즉시 끊깁니다.
- 세션이 곧 신원입니다. 잃어버리면 속한 팀과 남남이 되고, 되찾는 길은 초대코드로 다시
  들어오는 것뿐입니다.
- 한 사람이 최대 3개 팀에 속할 수 있고, 팀마다 별도의 멤버 신분(닉네임·캐릭터)을 갖습니다.
  이미 들어와 있는 팀에 초대코드로 다시 참여하면 정원을 더 쓰지 않고 닉네임만 갱신됩니다.
- 팀원이 모두 나가면 그 팀은 DB에서 삭제되고 초대코드도 함께 사라집니다.
  아무도 없는 팀은 되살릴 방법이 없으므로 빈 껍데기를 남기지 않습니다.
